# Recruiting framework

Principle: understand **why the company is hiring** before writing anything.

## Notes exchanged between steps
| Step | Agent | Output |
|---|---|---|
| 1 | `company-researcher` | `company-brief`: activity, priorities, role-relevant facts, hypotheses, 3–5 differentiators or "insufficiently documented", evidence table, `company_profile` (type, unit, triggers) |
| 2 | `job-intelligence` | `job-analysis`: requirement → business problem → expected result → evidence needed; said vs assumed; posting status |
| 3 | `candidate-evidence` | evidence cards + gaps + questions |
| 4 | `recruitment-strategist` | hiring context, matrix, value proposition, 1–3 arguments, `adaptation` per lever, differentiation test, CV/letter placement |
| 5 | main skill | `package.json` → DOCX/PDF + dossier |
| 6 | `application-auditor` | blocking / non-blocking findings |

Steps 1–3 are independent: run them in parallel. Step 4 needs all three.

## Strategy matrix
`priority need → concrete evidence → potential value → confidence (high/medium/low) → placement (CV/letter/both/interview)`
- Needs come from the posting (said) and confirmed company facts; hypotheses are labelled.
- Value is stated as a plausible contribution, never as a promised result.
- Confidence: high = evidence directly matches; medium = transferable or prototype; low = gap.

## Hiring context and adaptation
Why hire now, which problem the hire solves first, which risk the hiring manager wants reduced: then one
adaptation per lever, each traced to claim/requirement ids. Company size changes the questions, not the
answers: see [company-context.md](company-context.md).

## Value proposition
One or two sentences the candidate can defend in an interview, built from the top 1–3 arguments.

## Differentiation test (mandatory for `package`)
For another company with the same title, which evidence, wording and motivation would change, and why?
If only names change, redo research or strategy. Do not force a difference the sources do not support:
with limited research, say so and personalise from the posting.

## When to delegate
| Request | Agents |
|---|---|
| Typo, single bullet rewrite, formatting | none |
| `audit` of existing documents | `application-auditor` (+ `company-researcher` only to verify company claims) |
| `projects` (which projects to show) | `candidate-evidence` (+ `job-intelligence` if a posting is given) |
| `create` without a target posting | `candidate-evidence` |
| `tailor`, `cover-letter`, `package` | all five |

## Interview argument (dossier)
For each core argument: likely question, STAR-style talking points from evidence only, honest gap answer.
